## Problem

Machine failures are rare compared with normal operation. A model that always predicts "healthy" looks accurate and is useless. I needed a comparison that would not hide the rare cases.

## Approach

Pick the model by F1 instead of accuracy. In this data about 23% of samples are failures, so a model that predicts "healthy" every time already reaches 77% accuracy.

The sensor data is synthetic. I generate it with configurable failure patterns, which gives full control over the failure rate and keeps the whole pipeline reproducible from one seed.

## Implementation

- 22 features derived from 8 raw sensor readings: interaction terms, z-score anomaly flags, an anomaly count per observation, and machine age bins.
- Automated cleaning and missing value imputation.
- Five classifiers trained on a stratified train and test split: logistic regression, random forest, gradient boosting, XGBoost and an RBF SVM.
- An evaluation report with a metrics table, a confusion matrix and feature importances, generated on every run.
- 14 pytest tests, fixed random seeds, and a Dockerfile that runs the pipeline with one command.

## Current status

Finished and public on GitHub. Oversampling the failure class and hyperparameter tuning are the next steps listed in the repository, and neither is done yet.

## What I learned

Accuracy would have told me all five models were fine. F1 and recall showed that none of them is good enough to rely on yet.
