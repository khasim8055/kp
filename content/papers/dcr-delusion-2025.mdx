## Problem

Many teams share synthetic data instead of real data. To check it is safe, they often run one quick test called Distance to Closest Record (DCR). If the fake rows are no closer to the real training rows than some other real rows are, the data counts as private. This paper asks whether that test actually measures privacy, by putting it next to a real attack.

## Method

The authors ran the same synthetic data through two checks and compared what each one said.

  <FlowStep n={4}>Take the 5th percentile of both sets of distances</FlowStep>
  <FlowStep n={5}>If the synthetic rows are at least as far away as the holdout rows, the data passes as private</FlowStep>

## What I'd question

It is still a preprint, so the results have not been through peer review yet. All datasets are public census and banking data, not health records, so I want to see the same test on clinical data. The main experiment attacks only the 100 most vulnerable looking records per setup, and the diffusion results rest on 10 models each. None of this changes the main point, but it shapes how far I would push the numbers.

## How I'd use it

I used to think that if synthetic data looks different from the real data, it is safe. This paper showed me that looking different and being private are not the same thing. The distance test only catches near copies, while a real leak can hide in one rare detail, like a country only one person comes from. Adding a rule for rare values would not fix it either, because leaks can also come from combinations of ordinary values. The better question is not "how similar is this data" but "could an attacker find someone in it". This is the starting point of my MSc thesis on agentic privacy auditing of synthetic health data, where I test whether an LLM agent can reason like an attacker and catch leaks that simple metrics miss.

## Reproduce it

I have not run this yet. The authors build on public tools: reprosyn for the classical generators and MIDSTModels for the diffusion models.
